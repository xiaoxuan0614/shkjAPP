# 维修报价修改边界

## 完工前报价决定与审批（2026-10-27）

- quotationRequired 未返回布尔值时，直接在完工页选择“需要报价/无需报价”，不默认勾选；需要报价的底部按钮为“去填写报价单”。无需报价只填写完工说明，先调用 quotation/decision（false，reason 复用完工说明），确认服务端保存成功后再调用 completion/submit。任一步失败停止后续流程；无需报价已保存而完工失败时，重试只提交完工。后端未授权则不开放修改。
- false：不展示价格输入，完工申请显式提交数值 finalAmount: 0，不提交 amountChangeReason；true：展示最终维修价格，提交时仍须已审批并经客户确认的价格，价格变化必填原因。
- 本日核对 Apifox：POST /repair/quotation/decision，true 携 faultScope/items 一次提交并启动 repair_ops_quotation，负责人所属部门主管 → 市场主管（market_manager）。历史节点 gm / GM_REVIEW 仍沿用编码，不再描述为总经理。false 只传 reason，不传明细或故障范围。不重复调用通用 start 或旧 quotation/submit。
- 仍复用 /repair/application/review 处理审批；真实服务模型启用与审批业务联调未在本轮执行。

用户确认规则：需要报价的，在客户确认后锁定；无需报价的，在提交完工后锁定。锁定后不能修改报价信息或切换是否需要报价。

移动端仍要求详情 `canChangeQuotationDecision === true`，不会用前端判断放开后端拒绝的权限。补充客户确认历史、无需报价完工提交记录、工单终态的前端防护，表单提交与入口统一使用此判断。

无需报价且可修改时，报价管理标题右侧显示“修改报价信息”，直接进入修改页；锁定后仅保留已有记录的查看详情。需要报价仍保留既有审批中撤回修改流程，不绕过在途审批。

后端需同步维护 canChangeQuotationDecision 并在报价决定接口校验：客户确认后不可改；无需报价提交完工后不可改（已提交即锁定，不因驳回或撤回自动解锁）。本仓库只修改移动端；未验证真实后端是否已采用该规则，未部署。
