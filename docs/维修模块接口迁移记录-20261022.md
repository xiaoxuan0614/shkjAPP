## 续接完成：报修修改与取消

2026-10-22 读取最新 Apifox 后已接 POST `/repair/order/reportEdit`、POST `/repair/order/reportCancel`。报修详情底部分别按 canEditReport / canCancelReport 展示修改、取消，即使报修人无维修详情权限也可办理；具备维修详情权限时，更多菜单也提供对应入口。列表不追加逐条详情查询。

修改复用报修表单，回显客户/分期/产品/故障/报修时间/备注/原附件，保留原报修姓名；修改原因必填。上传后提交完整保留附件 ID，不传 version/requestId，不调用新建或重派接口。取消独立填写原因（最多1000字符），只提交 orderId/reason，成功后按接口响应刷新为关闭状态，相关操作按钮隐藏，列表返回后重新查询。普通写结果不明沿用暂停提交、要求重新核对机制。

后端资格：原报修账号、PENDING、无任何后续业务；仅初始派单和本人修改不阻断。前端读取动作权限，不单靠待处理状态判断。后端取消为 CLOSED + REPORTER_CANCELLED，不删记录、不生成评价、不走维修关闭审批。

新增回归涵盖两个路径和请求白名单、空原因/超长原因、编辑回显、附件保留、原姓名及时间保留、报修人无维修权限仍可操作、取消后按钮隐藏、新建与编辑状态隔离。真实后端部署及业务提交未验收。

## 已完成

| 部分 | 当前实现 |
| --- | --- |
| 报价权限 | 入口、更多菜单、表单提交均检查 `result.canChangeQuotationDecision === true`。缺失或 false 不允许修改，不用报价文案或 canOwnerApply 推断。审批中不重复提交需要报价，可按权限改无需报价。 |
| 完工价格 | 需要报价时要求最终金额；与最新报价的 customerConfirmedAmount 按分比较，不一致必须填写 amountChangeReason。一致不传旧原因；无需报价只传 orderId、description。需要报价但缺少客户确认价时阻止提交。 |
| 签到 | 四字段 orderId、repairMethod、longitude、latitude；读取响应 recordId，再显式查询 work/detail，不再用 orderId 代替作业 ID。 |
| 日志接口 | 移除 work/log；未提交记录使用 saveDraft/submit，已提交记录使用 update。成功响应按本次日志详情解析，整单另行刷新。 |
| 草稿 | 不做业务必填校验；仍检查后端 canSaveDraft。上传本地附件后保存其 ID，不把草稿当作正式提交。 |
| 权限与角色 | 根据本次 workRole 和 canSaveDraft/canSubmit/canUpdate/canEnd；协助日志只要求维修内容。历史编辑显式携带 recordId，由接口权限放行。 |
| 关联全量保存 | fileIds、persons、vehicleValue、materialUseIds 始终保留完整选中值；已保存但不在当前候选中的关联不静默丢弃。支持移除已有附件。 |
| 用人、用车 | 第三页可选择本单 personOptions 和公司 vehicles；人员为弹层多选，选择不替代协助申请或签到。 |
| 用料 | 可登记实际用料，并选择本次日志关联的使用记录 ID；候选按本人领料来源和未绑定其他作业过滤，既有引用仍保留，归属由后端再次校验。 |
| 详情 | 展开每次日志显式请求 work/detail，展示该次内容、附件、人员、车辆和用料，允许按返回权限编辑。 |
| 签退 | 仅传 orderId、recordId、location；不传报价、维修结果、version。完成去向仅控制页面，不自动发起完工审批；复修和协助返回详情。 |
| 重复提交防护 | 已迁移维修请求不再发送 version/requestId。一般写请求网络结果不明时暂停当前页面提交，要求重新打开详情核对；成功但刷新失败不直接重发。用料刷新失败提供只 GET 的刷新操作。签退按接口明确幂等规则允许重试。 |

负责人仍为三页：报修信息 → 维修信息 → 用人用车用料。表单沿用项目的分区与底部操作布局；人员/用料列表点击输入框后才展示。

注意：客户确认金额是已审批报价后最终经客户确认的业务基准，不能拿未经客户确认的报价合计代替；仅审批通过还不能提交需要报价的整单完工。

## 2026-10-22 续接：剩余业务入口已接入

新增 `RepairAdditionalForm.vue` 和 `repairAdditional.ts`，不再把下列九项列为“未接接口”。入口在维修详情底部“更多”中分类展示，评价权限成立时还有主按钮；列表、详情权限与操作权限分开，最终资格及结算由后端核验。

| 功能 | 已接接口及页面行为 |
| --- | --- |
| 确认 / 作废用料 | POST `/repair/material/confirmUse`；选择待确认使用记录，提交 useId、confirm；作废必填原因。 |
| 损坏 / 遗失核销 | POST `/repair/material/writeoff`；本人原领料多行选择，DAMAGE/LOSS、正数量最多4位小数、逐行原因、整体说明、可选附件；同来源同类型禁止重复。申请审批，不在前端扣库存。 |
| 终止未出库余量 | POST `/repair/material/closeRemainder`；按 stockApplyId 去重选择原库存申请，必填原因；不代替退库。 |
| 撤回申请 | POST `/repair/application/withdraw`；只列本人 PENDING 申请，传 applicationId 和原因；不复用审批 taskId。 |
| 移出协作成员 | POST `/repair/member/exit`；选择 ACTIVE 成员，传 members[].id，而非用户 ID，必填原因；历史保留。 |
| 联系资料 | POST `/repair/order/contact`；按 canEditContact 显示，回显地址、联系人、电话，全部及原因必填；详情只读展示更新后资料。 |
| 补卡时间审批 | POST `/repair/clockCorrection/submit`；本人已有作业，选择开始/结束时间，不可倒置或未来时间，可附证明；审批生效后才改工时。 |
| 定位失败缺卡登记 | POST `/repair/work/missingClock`；独立兼容表单，按文档提交阶段、方式、位置、故障、内容、结果、原因及 afterFileIds；已修复必须有照片或视频；不把旧字段带入正常日志。 |
| 回访评价 | POST `/repair/evaluation/submit`；按 canEvaluate 显示，三个评分独立选择1～5，不默认满分；意见选填；详情展示 EVALUATED 只读结果。 |

卡片同步修正：报修/维修列表状态仅保留右上角，取消底部重复状态；待处理保留等待时长；“维修负责人”改为“维修人”；报修时间统一 `YYYY-MM-DD HH:mm:ss`，不显示 ISO 中间 T，空值显示占位。
