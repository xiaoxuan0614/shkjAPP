## 最新业务调整：多部门邀请，审批后独立指定人员

本节替代下文内部协助申请时选人、userIds 批量提交的方案。

- 移动端内协申请改为部门多选，每个部门分别填写必填协助原因；跨页选择、取消、重新选择、删除与内外协切换保留对应输入。部门不可重复。部门目录读取现有 `/sys/sysDepart/queryTreeList`，不是协助人员列表；是否允许邀请该部门仍需后端业务校验。
- 外协单选一家单位，填写人数、人均预计工时和原因，展示人数乘工时的预计总工时；实际工时不由申请量替代。
- 目标审批：运维主管先审 → 各受邀部门并行审批，部门之间全部通过、同部门多个主管任意一人办理 → 审批结束。任一部门驳回整单退回。
- 审批全部结束后，为各部门生成独立的“待指定内协人员”业务待办。部门主管指定本部门成员，不通过审批接口选人；各部门分别指定，指定成功的成员加入维修单。前端不能用“审批通过”替代“已经加入”。
- 当前页面仅完成新表单和校验，**未开放新协助提交**：不将新表单发送到旧 userIds 或审批时 assignedUserIds 协议，不伪造指定人员接口。内外协均显示待接口同步提示，输入保留在当前表单，未持久化为后端草稿。

### 本次修改

- 附件统一改为 `POST /sys/common/upload`，`file` + `biz=repair`；读取顶层 `message` 的本地相对路径，拒绝业务失败、外链和无效路径。新附件路径与已保存的快照 ID 可随原 `fileIds` 一起提交；已有快照下载接口不变。下文“新上传返回附件 ID”的旧描述不再适用。
- 内部协助候选改为 `GET /repair/options?type=collaborationMembers`，展示部门；提交一次 `POST /repair/collaboration/submit`，字段为 `orderId/userIds/reason`，1–20 名不重复人员，不再逐人发送、不传角色。全部审批完成后由后端统一生效。外协保留单人申请协议及部分成功处理。
- 报价审批中、待客户确认时，仅当 `canChangeQuotationDecision=true` 才显示“改为无需报价”；不能借此重新提交报价明细。保留无需报价原因、终止旧流程的提示，增加 WITHDRAWN 状态回显。报价客户确认后的锁定仍由后端权限控制。
- 移除“申请补卡”“登记缺卡作业”入口，并在公共动作权限处禁用，避免仍可进入提交。历史记录和历史接口类型保留，不删除数据；正常签到、签退不受影响。
- 维修领还料 `/stock/apply/add` 保留 `usageType=MAINTENANCE`、`repairOrderId`、相应 `periodId`，领料 OUT、还料 IN。明细传 `materialId/applyQty`，按基准单位填写，不传 `bizType`、`repairSourceItemId`、`unitQty`。还料新增必填非负 `unitPrice`，可填明细备注。
- 还料改为按物料选择，不再绑定原领料行。后端按当前用户、维修单、物料分配原领料余额，禁止退他人领用量。前端明确提示目录不代表个人可还余额，实际额度由后端校验。不在前端虚构余额，也不按提交行下标操作后端拆分后的明细。

## 续接完成：报修修改与取消

2026-10-22 读取最新 Apifox 后已接 POST `/repair/order/reportEdit`、POST `/repair/order/reportCancel`。报修详情底部分别按 canEditReport / canCancelReport 展示修改、取消，即使报修人无维修详情权限也可办理；具备维修详情权限时，更多菜单也提供对应入口。列表不追加逐条详情查询。

修改复用报修表单，回显客户/分期/产品/故障/报修时间/备注/原附件，保留原报修姓名；修改原因必填。上传后提交完整保留附件 ID，不传 version/requestId，不调用新建或重派接口。取消独立填写原因（最多1000字符），只提交 orderId/reason，成功后按接口响应刷新为关闭状态，相关操作按钮隐藏，列表返回后重新查询。普通写结果不明沿用暂停提交、要求重新核对机制。

后端资格：原报修账号、PENDING、无任何后续业务；仅初始派单和本人修改不阻断。前端读取动作权限，不单靠待处理状态判断。后端取消为 CLOSED + REPORTER_CANCELLED，不删记录、不生成评价、不走维修关闭审批。

新增回归涵盖两个路径和请求白名单、空原因/超长原因、编辑回显、附件保留、原姓名及时间保留、报修人无维修权限仍可操作、取消后按钮隐藏、新建与编辑状态隔离。真实后端部署及业务提交未验收。
