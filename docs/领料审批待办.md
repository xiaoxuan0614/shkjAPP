# 领料审批待办

## 入口与接口

首页待办识别 `PROJECT_MATERIAL_APPLY_APPROVAL`、`STOCK_OUT_APPROVAL`，从 `actionParams.applyId` 或 `bizId` 获取申请单 ID，打开底部领料审批弹窗。

- 详情：`GET /stock/apply/queryById?id=...`。
- 明细：`GET /stock/apply/items`，参数 `applyId`、`pageNo`、`pageSize: 20`，支持继续加载和失败重试。
- 整单审批：`POST /stock/apply/approve`，参数 `applyId`、`approvalResult: AGREE | REJECT`、可选 `approvalComment`；驳回原因必填并去除首尾空白。审批不直接执行出库。
- 三个接口均额外检查 `success: false`，避免业务失败被当成成功。

仅待审批（`status: 2`）的申请可操作。项目领料要求当前分期已接受邀请的有效项目经理成员关系；维修领料按 `userIdentity: 2` 且申请部门精确匹配账号 `departIds` 判断，不再额外要求 `mtl:apply:approve`（2026-10-23 与 PC 对齐）。劳保仍额外要求该菜单权限，非项目入库保留 `mtl:goods:io`。提交前重新读取申请和审批资格，后端仍负责最终鉴权；本次没有变更角色授权或新增接口。

## 延续现有弹窗布局

延续首页延期审批弹窗：底部打开、标题和关闭入口、独立滚动正文、固定双按钮操作区。通过需二次确认；驳回显示原因输入。填写原因后关闭使用本组件提供的独立 wd-message-box（root-portal、zIndex=3000）确认丢弃，避免被 zIndex=2000 的底部弹窗遮挡；取消或失败保留原内容。请求序号防止旧详情覆盖新申请，提交中禁止重复提交和关闭。

首页待办每行固定 68px，滚动区域最多五行（340px），不足五行随内容缩短；按每页 20 条加载，滚动到底加载后续页，并提供加载、空数据及重试状态。
