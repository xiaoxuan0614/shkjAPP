# SHKJ 移动端菜单、角色权限与 PC 端对应

> 最后更新：2026-09-01。PC 与移动端共用菜单节点定义，但使用独立角色授权关系。移动端工作台只展示当前角色移动端授权结果中配置了 `miniAppPath` 的入口，按钮权限决定可执行动作，项目数据范围最终由后端接口控制。

## 1. 当前移动端入口机制

- 所有页面静态注册在 `src/pages.json`。
- `src/router/index.ts` 同时校验登录态和已成功加载的授权菜单，白名单为登录页。权限服务异常时不再把网络错误误报为“无权限”，页面请求仍由后端最终鉴权。
- `src/pages/role/index.vue` 是开发期角色页面预览入口，不是正式角色菜单。
- 公共 tabBar 为“首页 / 我的”；首页 `/pages/home/index` 的业务概览、日常办公和车辆入口以后台移动端权限为准，未配置入口不渲染；待办和项目动态保持独立展示。
- 后端必须继续做数据权限和操作权限校验，不能依赖前端隐藏按钮保证安全。

## 3. PC 端如何配置菜单和角色

PC 端在“系统管理 → 菜单管理”配置，正式事实源是后端菜单表：

1. 一级菜单使用 `LAYOUT`；子菜单的 component 对应 PC 仓库 `src/views/`，不带前导 `/` 和 `.vue`。
2. 项目详情、领料、还料等虽不显示在侧边栏，也必须建立隐藏菜单，否则 PC 按钮跳转会 404。

2026-09-11：移动端项目详情待验收时“提交验收”按钮需 `project:acceptance:submit`；接口同时校验项目成员。此权限不同于办理内部/客户验收的权限，不互相替代。本次仅接入按钮权限判断，未修改正式角色授权；账号未获授权时不显示提交按钮。
3. 在子菜单下增加“按钮”类型权限项，再到“角色管理 → 授权”的“移动端权限”页签单独勾选。
4. 修改后重新登录；若仍未生效，检查后端菜单/Redis 权限缓存。

## 5. 移动端权限接入机制

当前接入闭环：

1. 登录后调用 `/sys/permission/getUserPermissionByToken` 读取当前用户授权菜单树，递归过滤并保存有效 `miniAppPath`；禁止使用系统全量菜单接口。
2. 再调用 `/sys/permission/getPermCode` 保存按钮权限码。按钮权限加载失败不能拖垮菜单加载；具体业务按钮必须使用后端已经确认的权限码，不能自行编造。
3. Pinia 权限仓库持久化菜单和权限码，账号切换、退出及 401 时统一清空。
4. 公共首页保持墨刀工作台结构；已成功加载权限时，未授权入口锁定，详情页按所属业务入口继承访问范围。权限接口异常时允许进入页面，由业务接口返回 401/403，避免前端误判。
5. 后端仍负责接口操作权限和数据权限，前端隐藏入口不能替代服务端鉴权。

“确认到货”在 PC 项目列表和移动端项目详情共用 `project:arrival:confirm`；仅 `IMPLEMENTING/DEBUGGING`（兼容历史 `DEBUG_COMPLETED`）且未到货时显示。2026-08-31 已回读真实后台“项目管理”列表菜单下该按钮节点，权限码正确且状态有效；具体授予哪些角色仍按业务责任配置。

`src/pages/role/index.vue` 仍只用于开发预览，生产入口已移除，且不在授权页面映射中。

## 6. 数据权限怎么配置

菜单权限、按钮权限和数据权限是三层，不可互相替代：

1. 在“系统管理 → 菜单管理”找到承载列表接口的 PC 菜单，使用“数据权限”维护规则。
2. 在“系统管理 → 角色管理 → 授权”选中该菜单，再进入“数据规则”勾选规则并保存。保存接口为 `POST /sys/role/datarule`，查询接口为 `GET /sys/role/datarule/{permissionId}/{roleId}`。
3. 项目经理的数据范围应是：合同/项目经理为当前用户，或当前用户在 `/project/member/list` 中存在已接受成员关系。这个条件涉及项目成员表关联，不能只靠移动端前端过滤。
4. 如果 `/project/project/projectPeriodList` 后端已经按当前账号处理上述范围，PC 与移动端天然一致；若没有，后端必须补充接口级数据范围，不能在移动端拉取全部项目后再隐藏。
5. 库管人员只授权“出入库管理”，库存和申请范围由 `/stock/apply/*`、`/stock/material/*` 后端权限控制；不要给库管角色勾选项目实施入口。
6. 系统管理员角色勾选完整菜单树及全部按钮权限；数据规则不得缩小管理员数据范围。移动端识别 `admin` 角色，并兼容登录信息未返回角色数组时的 JEECG 超级管理员账号，开放全部页面入口；这只影响入口展示，业务接口仍由 OA 后端执行按钮和数据权限鉴权。

项目经理角色 `project_management` 已按以下基线保存并回读：主页/首页、项目管理/项目列表、项目详情、编辑计划方案、物料管理下的领料与还料、资源管理下的车辆管理与车辆详情、实施管理/实施列表/查看日志/日志详情；按钮只授予 `project:implement`。库管人员只勾选出入库管理。移动端复用这些 PC 菜单的 `miniAppPath`，不再新增第二套同名一级菜单。
