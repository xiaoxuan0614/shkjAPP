# 维修用料统计明细与后端待办

## 已核对的接口

2026-10-29 在 Apifox「首汇OA / 维修模块」读取以下文档；未提交业务数据。

- `GET /repair/materialAccount/page`：`orderId`，分页；按物料 ID + 历史基本单位 ID 汇总。现有展示继续每页 5 条。弹窗补充 `confirmedUseQty`、`pendingUseQty`、`shouldReturnQty`、`remainingReturnQty`，保留 `outboundQty`、`actualReturnQty`、`consumedQty`、`availableReturnQty`。缺失值显示 `—`，不补零、不推导余额。
- `GET /repair/order/detail?id=维修单ID`：`materialLinks` 返回来源关联的 `stockApplyId`、`stockApplyItemId`、`linkType`（PICK/RETURN）、`sourcePickLinkId`、`handlerUserId`、`materialId`、`baseUnitId`、`outboundQty`、`createTime` 等；`materialUses` 返回 `pickLinkId`、`workRecordId`、`usedQuantity`、`useDescription`、`useStatus`、`handlerUserId`、`createTime` 等。
- 两个集合受当前用户权限裁剪，空集合不代表整单没有业务。来源记录的创建时间不能称为实际出库/入库时间；`outboundQty` 为来源行累计实际出库，不是某次执行流水。
- 现有库存申请详情页使用 `GET /stock/apply/queryById?id=申请单ID`、`GET /stock/apply/items?applyId=申请单ID`，审批记录使用 `/stock/apply/approvals`，入库记录使用 `/stock/ioRecord/list`。本次不改变这些接口或执行权限；从来源记录打开原申请单页面继续查看。

## 已实现

- 用料统计每行可点击，打开物料详情弹窗。显示数量汇总，分「领用与还料」「使用记录」两栏，前端每页 5 条。
- 仅点击时读取一次工单详情；切换页签和翻页不重复请求；关闭、切换维修单后忽略过期响应。请求失败可重试。
- 严格按维修单、物料、历史基准单位匹配。使用记录仅在自身物料与单位均缺失时通过精确 `pickLinkId` 关联；不按名称拼接、不混入其他单位。
- 有 `stockApplyId` 时显示“查看申请单”，进入已有申请详情页，详情页继续按后端权限校验；不自动执行申请或出入库。
- 经办人仅从可见成员姓名快照或负责人姓名匹配，缺失则显示“姓名未返回”，不把 ID 当姓名。
- 报价详情去掉当前审批节点文案，审批阶段统一显示“报价审批中”。

## 尚未完整实现，需后端配合

现有接口可以追溯关联申请和使用记录，但本次核对的维修来源集合没有完整的申请数量、审批状态、实际还料入库量、逐笔库存执行人员/时间。当前弹窗引导查看原申请单，没有伪造这些数据；没有将工单来源集合视作完整流水。

建议新增**单物料分页流水接口**（路径待后端确认，前端未调用任何猜测路径）：

请求：`orderId`、`materialId`、`baseUnitId` 必填；`pageNo`、`pageSize`；可选记录类型 `APPLY/PICK/USE/RETURN`、经办人。返回 `records/total/pageNo/pageSize` 与实际查询三元组。提供可见范围/是否完整标记，避免权限裁剪被误认为完整记录。

每条记录建议提供：

| 内容 | 建议字段与含义 |
| --- | --- |
| 唯一来源 | `recordId`、`recordType`、`stockApplyId`、`stockApplyItemId`、`pickLinkId`、`sourcePickLinkId`、`workRecordId`，按记录类型返回 |
| 申请 | `applyNo`、`applyQty`、`approvedQty`、`applyStatus`、`applyStatusText`、申请人 ID/姓名、申请时间 |
| 实际领用/还料 | 库存执行记录 ID、执行基本数量、实际出库/入库时间、执行人 ID/姓名、经办人 ID/姓名、执行状态/字典文本 |
| 使用 | `usedQuantity`、`useStatus` 及文本、使用说明、关联维修日志、经办人姓名、记录/确认时间；作废/替代记录保留状态与关联链 |
| 单位 | `materialId`、`baseUnitId`、`baseUnitName`；所有数量用历史基准单位，不跨单位求和 |

口径：申请量≠批准量≠实际出库量；审批通过≠库存执行完成；还料申请量≠实际入库量；草稿用料不占用，待确认是 `consumedQty` 子集，确认后不得重复扣量；撤回/驳回/关闭释放未执行占用但保留已执行事实。分页明细不能在前端重新求和替代总账。
