# 维修日志用料新版对接与时间轴

## 本次修正

- 用户确认提交维修日志使用 `POST /repair/work/submit`。用料按 `materialItems: [{ pickLinkId, quantity, description? }]` 随日志提交；不再单独登记，不再发送 `materialUseIds`。
- 草稿 `POST /repair/work/saveDraft`，修改 `POST /repair/work/update`，使用同一数组；传空数组表示无用料。说明不再单独必填，省略后由后端使用维修内容。
- 本人本单 PICK 候选直接读取 `GET /repair/order/detail` 的 `materialLinks`，用 `outboundQty/availableUseQty` 判断出库和余额；不再循环查询 `/stock/apply/items`。
- `GET /repair/work/detail` 回显 `materialItems`，详情也按新数组展示；旧日志仅在能够完整解析旧 useId 明细时迁移，缺失明细禁止覆盖保存。
- 未提交的选料数量保留在父表单，换步骤不丢失；草稿不触发独立使用登记。已确认用料禁止改删。新选料提交校验可用量；修改已有已提交用料的余额差额交给后端事务校验，避免把已占用量重复扣减。

## 页面

- 用料与项目实施一致采用紧凑的物料信息、可用量、数量/单位、移除行。
- 选择弹窗包含名称/编码搜索、多选、全选、规格和余额、完成按钮；没有独立用料说明和登记按钮。
- 维修处理日志改为时间轴：操作人、时间、操作名称及内容，重复内容不再重复显示。保留分页和失败重试。

## 接口证据与验收边界

接口数组与余额规则依据后端 2026-10-23 共享对接记录（materialItems 整批登记及权威候选余额），提交路径经本轮用户确认。旧 Apifox 分享页未展示维修模块，未据此声称已逐字段核对新版 Apifox。

前端回归覆盖候选范围、草稿、数量、确认保护、旧日志安全和新提交数组。未向真实后台提交业务数据；线上余额扣减及并发事务仍须联合验收。

验证结果：资源、页面、API、滚动分页、协助回归通过；最终 H5 构建通过。隔离浏览器验证时间轴、物料弹窗、数量行及回显；320/390/768 宽度无横向溢出。模拟保存草稿请求包含 `materialItems[{pickLinkId,quantity}]`，无 `materialUseIds`，旧库存明细读取及独立用料登记请求均为 0。以上接口由测试拦截响应，不是线上提交验收。
