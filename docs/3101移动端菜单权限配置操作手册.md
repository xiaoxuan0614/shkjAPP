# 3101 页面移动端菜单权限配置操作手册

> 适用页面：SHKJ-OA `http://localhost:3101` 的“系统管理 → 菜单管理”和“系统管理 → 角色管理”。  
> 目标：移动端复用 PC 端已有菜单和角色权限，不再另外创建一套同名的移动端一级菜单。

## 一、先理解这三个配置

| 配置          | 作用                                                           |
| ------------- | -------------------------------------------------------------- |
| PC 路径、组件 | 决定 PC 端点击菜单后打开哪个页面，本次不要修改                 |
| 移动端路径    | 决定这个 PC 菜单对应哪个移动端页面，以及角色能否进入该功能     |
| 角色授权      | 决定某个账号能看到哪些 PC 菜单和移动端入口                     |

移动端会递归读取当前角色获权的菜单树。工作台外观按墨刀原型固定，未授权入口显示锁定；移动端路径应填写在真正代表该功能入口的菜单记录上。父子菜单不要重复填写同一个移动端路径。

## 二、按照当前菜单页面逐行修改

进入“系统管理 → 菜单管理”，在对应行点击“编辑”，只修改“移动端路径”。PC 路径、组件、菜单类型和父级关系暂时不要动。

| 当前菜单行              | 当前层级      | 移动端路径应配置为           | 本次操作                            | 说明                                      |
| ----------------------- | ------------- | ---------------------------- | ----------------------------------- | ----------------------------------------- |
| 首页                    | 一级菜单      | 留空                         | 不改                                | 移动端已有自己的公共首页                  |
| 项目管理                | 一级菜单      | `/pages/ops/project`         | 保留                                | 项目模块在移动端的唯一入口                |
| 项目管理 → 项目管理     | 子菜单        | 留空                         | **清空当前的 `/pages/ops/project`** | 不能和父级重复配置                        |
| 项目管理 → 新增项目     | 子菜单        | 留空                         | 不改                                | 不单独出现在移动端首页                    |
| 项目管理 → 合同信息     | 子菜单        | 留空                         | 不改                                | 从项目业务页面进入                        |
| 项目管理 → 新增计划方案 | 子菜单        | 留空                         | 不改                                | 从项目业务页面进入                        |
| 资源管理 → 车辆管理     | 子菜单        | `/pages/ops/vehicle`         | 保留                                | PC 归入资源管理；移动端可直接作为车辆入口 |
| 物料管理                | 一级菜单/分组 | 留空                         | 不改                                | 当前不作为移动端独立入口                  |
| 查看日志                | 一级菜单      | `/pages/ops/implementLog`    | 保留                                | 实施日志入口                              |
| 低代码开发              | 一级菜单      | 留空                         | 不改                                | 不进入业务移动端                          |
| 出入库管理              | 一级菜单      | `/pages/stock/materialApply` | 保留                                | 库管申请记录和执行入口                    |
| 计划方案管理            | 一级菜单      | 留空                         | 不改                                | 当前没有对应的独立移动端首页              |

### 当前必须修改的一项

找到一级“项目管理”下面缩进显示的子菜单“项目管理”：

1. 点击该行右侧“编辑”。
2. 找到“移动端路径”。
3. 删除 `/pages/ops/project`，保持为空。
4. 点击保存。

修改完成后，表格里只能有一级“项目管理”这一行显示 `/pages/ops/project`，其子菜单不能再显示该路径。

## 三、不要新增第二套一级菜单

PC 与移动端共用同一套菜单记录和角色授权。正确关系如下：

```text
OA 已有一级菜单“项目管理”
├── PC 路径：/project
├── 移动端路径：/pages/ops/project
└── 子菜单：项目列表、新增项目、合同信息、计划方案……
```

因此不需要再新增“移动端项目管理”或“小程序项目管理”。新增第二套一级菜单后，角色授权页面会出现两个“项目管理”，后续很难判断应该勾选哪一个。

## 四、角色权限怎么勾选

进入“系统管理 → 角色管理”，找到角色后点击“授权”。移动端是否显示入口，取决于该角色是否拥有填写了“移动端路径”的菜单。

| 角色类型               | 至少勾选的入口菜单         | 根据 PC 工作需要再勾选             |
| ---------------------- | -------------------------- | ---------------------------------- |
| 项目经理               | “项目管理”、“查看日志”、“车辆管理” | 领料申请、还料申请及项目实施按钮 |
| 实施人员               | 一级“项目管理”、“查看日志” | 项目查看、实施日志相关按钮         |
| 车辆管理人员           | “车辆管理”                 | 车辆新增、编辑等按钮权限           |
| 库管人员               | “出入库管理”               | 申请详情、执行出入库等按钮权限     |
| 系统管理员             | 完整菜单树                 | 全部按钮权限                       |
| 同时承担多个岗位的人员 | 上述菜单按实际职责多选     | 对应子菜单和按钮权限               |

注意：

1. 勾选配置了移动端路径的菜单，移动端才能得到对应入口；如果它是子菜单，还需同时勾选其上级菜单以保持 PC 菜单树完整。
2. PC 端具体页面和按钮仍按子菜单、按钮权限继续勾选。
3. 不要为了移动端再新建角色；现有角色直接补充这些菜单授权即可。
4. 不同角色可以拥有同一个入口，最终能看到的数据仍由后端数据权限控制。
5. 系统管理员必须勾选完整菜单树和全部按钮权限；管理员不绑定会缩小范围的数据规则。移动端优先识别 `admin` 角色；为兼容当前登录响应可能不返回角色数组，也兼容 JEECG 超级管理员账号。该兼容只开放页面入口，接口操作和数据范围仍由 OA 后端鉴权。

## 五、保存后如何验证

菜单和角色授权保存后，使用对应角色的真实账号验证：

1. 在移动端退出当前账号。
2. 重新登录，让系统重新获取菜单权限。
3. 如果页面提供“同步菜单”，再点击一次“同步菜单”。
4. 检查移动端首页入口状态是否符合角色：项目经理的项目管理、今日实施、用料/还料和车辆入口可进入；库管的出入库入口可进入；未授权功能显示锁定。
5. 点击每个入口，确认分别打开项目、日志、车辆和出入库页面。
6. 确认移动端没有出现两个“项目管理”。

如果修改后仍然显示旧菜单，先完全退出并重新登录；仍不生效时，再检查该账号关联的角色是否正确、角色授权是否保存成功，以及后端菜单权限缓存是否已经刷新。

## 六、关于“运维工作台”

移动端公共首页 `/pages/home/index` 已承担墨刀综合工作台，不需要给它配置 PC 菜单，也不要把 `/pages/ops/home` 填到“查看日志”或“项目管理”上。

`/pages/ops/home` 属于早期角色页，正式首页不要再跳转到它；后续完成迁移后可清理该重复页面。

## 七、数据权限配置

1. 先在“菜单管理”选中项目管理列表对应菜单，点击“更多 → 数据权限”，确认是否已有项目范围规则。
2. 再到“角色管理 → 授权”，选中同一项目菜单并打开“数据规则”，给项目经理角色勾选规则后保存。
3. 角色数据规则查询为 `GET /sys/role/datarule/{permissionId}/{roleId}`，保存为 `POST /sys/role/datarule`。
4. 项目经理应只能取得“本人是项目经理”或“本人是已接受成员”的项目。成员关系需要关联项目成员表，若现有数据规则编辑器无法表达，必须在 `/project/project/projectPeriodList` 后端实现，不能靠移动端隐藏数据。
5. 库管角色的数据范围由库存和出入库接口控制，不要复用项目经理的数据规则。

验证数据权限时至少准备两个不同项目账号：项目经理账号只能看到负责/参与项目，库管账号能看到待处理出入库申请但不能进入项目实施。PC 与移动端使用同一账号各验证一次，结果应一致。


## 2026-10-26 APP 权限域修正

账号密码登录调用 `/sys/mLogin`，当前菜单和按钮统一读取 `/sys/permission/getUserAppPermissionByToken` 的 menu/codeList，不再使用 PC 登录令牌和混合权限来源。首页进入时重新检查权限（60 秒节流），升级缓存版本。原 `/sys/login` 会话须退出后重新登录；前端无法将旧 PC Token 转成 APP Token。角色授权仍在移动端页签分别保存，不新增或扩大角色权限。
