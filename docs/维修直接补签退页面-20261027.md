# 维修直接补签退：页面先行

> 2026-10-29 更新：用户确认前端直接对接，后端改为免审批。现已调用 POST `/repair/clockCorrection/submit`，传 orderId、recordId、effectiveEndedAt、reason，成功后回读 ENDED 才提示签退成功。下方“仅页面、不能提交”是历史状态，已被本次实现覆盖。详见《维修交互与接口核对-20261029.md》。真实免审批及工时更新尚待联调。

## 页面已实现

- 维修签退页增加“补签退”入口，弹窗参考项目补签退样式。
- 关联本人当前维修记录；显示签到时间，填写实际签退时间、未及时签退原因（必填，最多 500 字）。
- 时间不能早于签到或晚于当前时间；切换页面、工单或记录时关闭弹窗，防止串单。
- 当前入口复用本人记录可签退资格 `actions.canEnd`，无需当前定位成功即可填写补签退弹窗。正常签退逻辑保持不变。

## 接口待接

- 用户已确认维修补签退不走审批。现有 `/repair/clockCorrection/submit` 是补卡审批接口，不用于本入口。
- 不调用 `/repair/work/end` 冒充历史签退，不伪造签退成功、结束状态或工时。
- 弹窗明确提示新接口未接通；确认按钮只校验填写内容并提示未提交，不发业务请求，填写不持久化。
- 后端需提供直接补签退的 URL、方法、时间字段及格式、原因字段、本人记录资格/重复提交规则、返回记录/工时结构。确认后再接入提交、成功回读及后续办理。
