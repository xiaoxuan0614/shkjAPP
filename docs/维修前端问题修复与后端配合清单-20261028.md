# 维修前端问题修复与后端配合清单

日期：2026-10-28。范围：移动端，依据《维修全流程实测-20261027.md》。未修改后端、权限、审批配置、排班；本轮不新增业务提交或库存操作。

## 已修改

1. 并行入口：主按钮优先办理审批时，“更多”仍提供继续填写当前日志、符合条件的客户确认维修入口。保留原权限及提交校验，不绕过审批。
2. 领料详情：申请数量改为申请量 requestedQty（applyQty/unitQty），不再取 approvedQty；实际出库数量限制仍按原审批/库存规则。
3. 首页待办：嵌入维修页面关闭返回时刷新首页；加载中的刷新请求合并为一次后续刷新，避免直接丢弃。
4. 维修记录摘要：优先使用已取得的日志详情正文；当前页缺摘要时最多补查5条详情，缓存并阻止同条并发补查。未返回正文不再直接断言“未填写”。
5. 审批内容：部门/原因、报价行、金额采用中文字段展示；过滤内部ID、节点键、分配状态等，去除相同字段/值的重复快照；保留 HIDDEN 字段权限和零金额。详情内审批同步使用此展示逻辑。
6. 报价审批状态：能取得当前任务时展示当前节点；否则显示“报价审批中”，不再把通用二级审批固定称为总经理审批。
7. 处理时间轴：过滤独立的 iteration/nodeKey/taskId/instanceId/assignmentStatus 等技术片段和独立状态码，保留业务文本、操作人、时间和事件分页。不擅自合并多个真实事件。
8. 附件：有明确 mediaType、MIME、文件名扩展名时识别照片/视频；缺元数据保持“类型未返回”，不猜测附件类型。完整回显仍需后端配合。
