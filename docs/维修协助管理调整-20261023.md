## 维修待办定位修正及报修信息字段

- 维修详情“报修信息”的展开区域移除项目名称，顶部项目标题、报修录入的项目选择及日志填写信息不变。

## 协助审批内容精简与详情防重

- 协助审批专用展示：内部协助按部门显示名称和对应原因，提示审批后独立指定人员；外协显示单位、原因及接口已有的人数/人均工时。名称缺失明确提示核对，不把 ID 当成人名或部门名。隐藏通用表单原始字段、JSON、重复原因，以及不相关的报价、客户确认价、最终维修价。仅有一个审批任务时不显示切换器；多个任务仍按各自 taskId 办理，审批意见及通过/驳回规则不变。
- 首页及完整待办列表共用入口：解析/打开期间锁定，完成后 600ms 防连点；异步弹窗入口等待其打开逻辑，失败后可重试。首页“查看详情”列表入口增加 600ms 防连点。
- 维修详情沿用请求锁，并忽略重复打开当前单据；维修日志详情增加请求中锁，已展示同一日志不重复请求，返回后再次打开仍重新读取，失败仍可重试；报价及协助弹窗已打开时不重复初始化。这不是全站路由拦截，不改其他业务页面的导航规则。
- 验证：待办防连点/锁释放、日志重复/失败重试/返回后迟到响应、协助摘要/缺失名称、多任务审批、API 与页面回归通过；H5 构建通过，保留既有 UnoCSS `-` 图标警告。隔离浏览器验证双部门审批内容无原始字段、重复原因和报价信息，320/390/768 宽度无横向溢出，无页面异常；没有提交真实审批。

## 已实现

- 维修详情新增统一“协助管理”区，右上角只有一个“邀请协助”入口；移除更多菜单中的重复协助邀请和通用移出成员入口。
- 分为“邀请记录”和“协助人员 / 单位”，每页 5 条。邀请默认折叠，展开显示部门原因、审批节点/意见（接口有返回时）、指定进度；外协显示单位、人数、工时等已有提交信息。
- 内协申请仍为多选部门、每部门填写原因；运维主管审批后，各受邀部门主管审批；全部审批结束后，由有权限的部门主管独立指定本部门人员。指定沿用 `requestId` 幂等重试，不改成审批时选人。
- 当前维修负责人填写原因，可直接移除生效内协，无需再走审批。非负责人、已移除人员、当前负责人本人和已完成/已关闭维修单不能办理；后端仍需校验权限、在途作业及物料。
- 协助人员展示加入时间、结束时间和退出原因；操作人仅在接口返回名称时展示。不会删除历史邀请、审批、打卡、维修记录或工时。
- 审批中的本人申请可撤回，撤回必填原因。撤回、驳回后的新版内协申请提供“修改重提”，复制部门和原因，不复制旧申请 ID、审批状态或指定结果；通过业务提交接口生成新申请，旧记录保留。已通过的申请不提供原地修改。
- 外协按单位目录 ID 汇总展示现有成员和历史，不用同名单位文字合并，也不逐个调用移出成员接口模拟整体结束。
- 非幂等写入结果不确定时沿用页面的暂停提交机制，要求重新打开详情核对；业务拒绝保留输入，不显示假成功。正常刷新同一维修单保留已展开的邀请，切换单据/账号才清理状态。

## 接口使用

| 功能 | 已确认接口/字段 |
| --- | --- |
| 展示协助 | `GET /repair/order/detail` 的 `applications`、`members`、`workflows` |
| 内协部门候选 | `GET /repair/options?type=collaborationDepartments` |
| 内协提交/修改重提 | `POST /repair/collaboration/submit`：`orderId`、`personType=INTERNAL`、`departments[{departmentId,reason}]` |
