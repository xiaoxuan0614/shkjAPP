# 局域网 H5 定位调试

浏览器只允许可信 HTTPS 页面获取精确位置。`http://localhost` 是浏览器的本机特例，其他设备通过 `http://局域网IP` 访问时无法完成项目签到定位。

## 开发机首次配置

macOS 开发机执行：

```bash
brew install mkcert
mkcert -install
pnpm setup:lan-https
pnpm dev:h5
```

证书生成后，Vite 会自动读取 `.cert/lan.pem` 和 `.cert/lan-key.pem`，原有 `pnpm dev:h5` 会以 HTTPS 启动。当前局域网地址以脚本输出为准。

## 其他电脑首次信任

只把开发机项目中的 `.cert/rootCA.pem` 复制给需要测试的电脑，不要复制 `lan-key.pem`，也不要复制 mkcert 根证书目录里的私钥。

Windows 操作：

1. 按 `Win + R`，输入 `certmgr.msc`。
2. 进入“受信任的根证书颁发机构 → 证书”。
3. 右键“所有任务 → 导入”，选择 `rootCA.pem`。
4. 完全退出 Chrome 或 Edge 后重新打开。
5. 访问脚本输出的 `https://局域网IP:9000`，允许浏览器定位权限。

如果仍显示“不安全”，说明根证书没有导入正确的“受信任的根证书颁发机构”。如果开发机 IP 变化，重新执行 `pnpm setup:lan-https` 生成包含新 IP 的服务器证书；使用同一 mkcert 根证书时，客户端不需要再次导入根证书。

## 验收

1. 地址栏必须为 HTTPS 且不显示证书警告。
2. 项目实施页选择项目和工序后，应先显示项目实施地点及 200 米范围；人员定位尚未完成时不再隐藏整张地图。
3. 定位超过 5 秒时页面会继续等待并提示“定位响应较慢”，20 秒仍未返回才判定超时；迟于原 5 秒阈值返回的有效定位仍会正常使用。
4. 定位状态应最终从“正在获取位置”变为正常、超出范围或明确的权限/设备/超时错误。
5. 电脑端 Chrome 无法定位时使用 Edge 复测，并确认 Windows 系统位置服务及当前站点定位权限均已开启。
6. 在配置地点 200 米内应允许签到；范围外继续按原规则阻止签到或要求异常说明。
