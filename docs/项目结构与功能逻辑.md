## 1. 技术结构

两端同步增量（2026-09-13）：到货确认范围包含 PENDING_APPROVAL，使用 payback_node 字典。`reworkMaterials.ts` 提供当前返工资格与额外额度查询，领料携带 reworkId；`projectAcceptance.ts` 与 `ProjectAcceptancePopup.vue` 提供分期当前轮内/客户验收、历史附件预览、统一结果提交及重新内验。无新页面路由，嵌入 projectDetail。验收结果必传当前 acceptanceId，报告通过统一上传后随 complete 保存，不提前 edit。后端审批链和 APP 登录权限迁移仍有缺口，见 [两端规则同步与后端待办](项目两端规则同步与后端待办.md)。

项目详情按钮（2026-09-13）：共享 `projectMembership.ts` 判断本分期已接受成员和角色2负责人。临时邀约仅负责人；工序完成仅负责人或对应现场负责人且限定当前返工轮。所有参与成员可领还料，仍需页面授权，还料路由传 periodId。到货确认在底部直显，沿用 `project:arrival:confirm` 和未到货状态门禁，提交前复查。领还料经理审批及经理本人免审批是用户确认目标，最新 Apifox 仍记载项目出库全员免审，后端待同步；前端只回显实际返回审批状态。

还料申请（2026-09-13）：`src/pages/ops/materialReturn.vue` 无状态限制调用 `/project/member/participatedProjects`，本地模糊搜索主项目/分期名；按 `periodId` 分页读取 `/project/materialAccount/page`，用 `remainingReturnQty` 和 `baseUnitName` 展示可还物料。本次数量 0 跳过，部分还料填写差异原因。确认后 `/stock/apply/add` 提交 `applyType=IN/bizType=RETURN/usageType=PROJECT/periodId`、可选备注和明细 `materialId/unitName/unitQty/remark?`；不调用旧 `/ops/materialReturn/*`，不直接入库或审批。

移动端待验收（`PENDING_ACCEPT`）底部仅保留“提交验收”，受 `project:acceptance:submit` 权限控制。确认后复查分期状态，通过 `/project/period/status` 传 `periodId/status=PENDING_ACCEPT` 启动内外部验收，后端实际进入 `ACCEPTING`。后续验收结果由各自权限办理；不使用废弃的 acceptance submit/start 接口。

项目详情顶部主项目名、分期名左右分列，下方显示字典状态和项目经理。实施情况前置，按工序独立呈现负责人 `siteLeaderName`、计划及剩余工期；进行中全部展开，未开始和已完成可折叠。单工序实施记录入口以 `processId` 初始化记录列表筛选。用料统计物料名称、品牌规格分行显示。

项目详情用料统计通过 `/project/materialAccount/page` 每页读取 5 条，列顺序为物料、计划、出库、已还、使用、待处置；已还对应 `actualReturnQty`。实施情况右侧进入 `implementRecords.vue`，通过 `/project/process/detail` 和 `work_type` 构建工序导航，通过 `/project/implementLog/list` 按分期、工序分页查询。点击记录进入 `implementRecordDetail.vue`，按日志 ID 调 `/project/implementLog/queryById`；内部人员从 `internalParticipantIds` 映射项目成员姓名。当前后端 `/project/implementLogPerson/list` 不存在，逐人签到与评价未接入。日志详情只读，用料来自该日志 `materials`，不以总账替代历史使用量。

项目详情“临时邀约”通过 `src/pages/ops/components/ProjectMemberInvite.vue` 选择人员和角色，人员搜索走 `/sys/user/list`，角色读取 `member_role` 字典；调用 `/project/member/addBatch` 提交当前 `periodId` 及 `records[{userId, memberRole}]`。沿用 PC 的受保护角色和重复角色限制，成功刷新详情，已接受邀请后才计入详情参与人员列表。

本项目是 Vue 3 + TypeScript + Vite 的 uni-app 多端工程，使用 Pinia 保存登录用户，Wot Design Uni 提供业务组件。主要目录如下：

| 目录                | 职责                                                           |
| ------------------- | -------------------------------------------------------------- |
| `src/pages/`        | SHKJ 角色业务页面，按 `customer/ops/stock/admin/dispatch` 分域 |
| `src/service/`      | 通用登录 API 与 SHKJ 业务 API；正式业务 URL 优先集中在这里     |
| `src/utils/http.ts` | 统一请求、token、租户、签名、错误处理                          |
| `src/store/user.ts` | 当前用户、token、租户和组织信息持久化                          |
| `src/router/`       | 根据 `src/pages.json` 生成路由并执行登录拦截                   |
| `src/components/`   | 页面布局、卡片、状态标签等复用组件                             |
| `mock/`             | 开发期流程数据，不是正式后端契约                               |
| `docs/`             | 当前结构、权限映射、规划、审查和更新记录                       |

启动链路为：`src/main.ts` 创建应用 → 注册 Pinia/组件/拦截器 → `src/pages.json` 生成页面路由 → 路由守卫校验登录态 → 页面通过 `src/utils/http.ts` 请求 `/shouhuiApi` 代理或正式服务。

### 1.1 登录链路

- 账号登录暂时移除图形验证码加载、输入和校验，按 SHKJ-OA 相同方式将密码做 AES-CBC/PKCS7 加密，仅提交 `username/password` 到 `POST /sys/login`。
- 短信登录通过 PC 端当前使用的 `POST /sys/sms` 发送登录验证码，再提交 `mobile/captcha` 到 `POST /sys/phoneLogin`。
- 登录成功必须同时取得 `result.token` 和 `result.userInfo.id`；移动端保存完整 `userInfo`，并从响应的 `departs` 解析当前部门名称，不再请求未收录于当前 Apifox 的 `/sys/user/appQueryUser`。
- 登录请求统一定义在 `src/service/auth.ts`，密码加密实现位于 `src/utils/cipher.ts`。认证成功后依次调用 `/sys/permission/getUserPermissionByToken` 和 `/sys/permission/getPermCode` 初始化菜单与按钮权限；认证、权限初始化需分别验证。
- PC 登录页还会调用 `/sys/loginGetUserDeparts` 做登录前多部门选择，但该接口未收录在当前 Apifox；移动端没有把它作为正式接口接入。若后端要求多部门用户登录前必选 `loginOrgCode`，需先在 Apifox 发布该契约后再增加选择 UI。

## 2. 标识与数据边界

- 2026-09-13 项目实施候选规则：`/project/member/participatedProjects` 传 `onlyUnfinishedProcess=true`，不再传 `periodStatus` 或按前端状态白名单筛选；选中分期后 `/project/process/detail` 传 `periodId + onlyUnfinishedProcess=true`。此规则覆盖下文旧实施候选状态描述，不影响领料等其他页面；签到前仍实时校验工序状态。

- 主项目使用 `projectId`，项目分期和移动端实施流程以 `periodId` 为主标识。
- 项目列表接口返回的 `periodId` 在移动端适配为页面通用 `id`，路由参数仍代表分期 ID。
- 项目列表展示的主项目编号优先读取 `projectNo`；领料申请契约中的 `projectNo` 提交所选分期的 `periodNo`，`projectName` 提交所选分期名称 `periodName`。这是当前 Apifox 的字段定义。
- 物料申请头与明细分开读取：申请头 `/stock/apply/queryById`，明细 `/stock/apply/items`。不得继续依赖已废弃的 `queryById.itemList`。
- 出入库执行统一提交 `{ applyId, itemIds?, items? }` 到 `/stock/apply/execute`，方向由申请头的 `applyType` 决定；部分执行通过 `items[{ itemId, executeQty }]` 指定本次数量。

## 3. 各角色功能逻辑

### 3.1 客户端 `src/pages/customer/`

首页进入故障报修、报修记录和个人中心。报修流程设计为：提交客户与故障信息 → 信息部门派单 → 运维接单和维修 → 客户确认签字/评价 → 完结。

当前 `/repair/*` 是移动端 Mock 契约，PC 项目中没有找到可直接复用且字段一致的正式维修接口，因此本轮没有伪接；需要后端提供报修申请、列表、详情、撤回、确认和附件协议后再联调。

### 3.2 运维端 `src/pages/ops/`

- 工作台：仅在当前账号存在 token 时加载首页数据，登录跳转期间不发出权限、项目和待办请求。顶部业务概览、日常办公和车辆管理只展示 `/sys/permission/getUserPermissionByToken` 返回且配置有效 `miniAppPath` 的入口，未配置的报修、维修、巡检等 Mock 模块不显示；待办主体通过 `src/service/todo.ts` 读取 `/sys/todo/page`，顶部数量使用分页 `total`。每条第一行以 `todoType` 查询 `todo_type` 字典并显示待办类型，第二行直接显示 `summary`，不展示接口 `title`、不逐条补查项目详情；字典不可用时使用同值类型兜底，未知类型保留原编码。点击 `actionKey=PROJECT_MEMBER_INVITATION` 时才调用 `/project/member/myInvitations`，用待办 `bizSubId` 匹配邀请记录 `periodId`，同一分期优先按 `bizId` 精确匹配记录 `id`；弹窗项目名称使用外层待办 `summary`，角色使用邀请记录 `memberRole_dictText`，并按 `bizSubId` 调用 `/project/contract/queryById` 读取 `contract.projectManagerUserName`，再通过 `/project/member/respond` 同意或拒绝；项目动态读取 `/project/project/projectPeriodList`。
- 接单与维修：设计为待接单 → 选择线上/线下 → 维修日志 → 审批/客户确认 → 关闭。目前 `/ops/repair*` 仍为 Mock。
- 项目列表：已接 `GET /project/project/projectPeriodList`，以项目分期为行展示。
- 计划审批待办：`PlanApprovalPopup.vue` 按待办 `bizSubId`（兼容 `actionParams.periodId`）打开近全屏折叠详情。方案文件、用料计划、人员配置、实施计划、实施位置、回款计划默认收起并展示数量摘要，支持同时展开；板块独立容错重试，列表读取完整分页。人员与外协分组，物料支持搜索，方案文件复用预览。仅 `project:plan:audit` 且分期 `PENDING_APPROVAL`、计划审批状态 `2` 时允许审批，历史缺失审批状态按待审批分期兼容；通过前核对六块并校验必需计划字段，提交前刷新项目状态。通过 `/project/period/status` 转 `IMPLEMENTING`，驳回转 `PREPARING`；接口不持久化驳回原因，界面明确提示。完成后刷新首页待办及项目；当前按现有 PC 调用规则实现，待最新 Apifox 与真实账号联调。
- 合同审批待办：点击 `PROJECT_CONTRACT_APPROVAL` 后，通过 `src/pages/home/components/ContractApprovalPopup.vue` 按分期查询 `/project/contract/queryById`，查看合同、附件及回款计划。回款计划以表格展示回款项、比例、计划金额和 `rollbackTime` 回款周期；合同详情不展示项目经理。点击“通过”后才按页调用 `/sys/user/list` 选择并明确确认项目经理，不在打开待办时预加载全量人员；确认后先用 `/project/contract/editWithPaymentRecords` 保存 `projectManagerUserId/projectManagerUserName` 及合同原回款计划，再调 `/project/contract/status` 提交 `periodId/status=1/approvalReason=''`，审批成功后调 `/project/period/status` 将分期状态更新为 `PREPARING`。点击“驳回”只要求填写 `approvalReason`，通过 `/project/contract/status` 提交 `periodId/status=0/approvalReason`，不修改项目经理或分期状态。操作失败保留已填内容，非待审批状态隐藏审批操作。
- 项目详情：已接项目基本信息、成员、工序、实施日志和用料计划；各子接口独立容错，单个子接口失败不清空基本信息。仅 `IMPLEMENTING/DEBUGGING`（兼容历史 `DEBUG_COMPLETED`）、未到货且拥有 `project:arrival:confirm` 时显示“确认到货”，预计日期只展示，确认接口不提交计划回款日期。
- 延期申请：已接 `POST /project/delay/add`，提交 `projectId/periodId/processId/delayReason/originalEndTime/expectedEndTime/delayDays`。
- 实施日志：业务闭环固定为“签到 → 填写并保存实施日志 → 签退”，以当前登录人和必填 `periodId + processId` 关联同一项目工序的最新实施记录，不使用独立流程 ID。选择分期和工序后通过 `GET /project/process/status` 校验状态；同一 `periodId + processId` 的上一轮未完成时禁止重复签到，并通过 `GET /project/implementLog/signOutDraft` 恢复，第二步草稿、下一步和日志提交统一通过 `POST /project/implementLog/signOutDraft` 保存。该草稿接口不提交 `hours`，`materials`、`outsources`、`internalParticipantIds`、`vehicleNo`、`mileage` 无填写值时不加入请求体。正常签退调用 `/project/implementLog/signOut` 且不传签退时间；补签退调用 `/project/implementLog/backfillSignOut`，必须选择有效实际时间并填写 `signOutRemark`；废弃接口 `/project/implementLog/edit` 不再调用。签退页“查看实施日志”直接返回实施记录页继续查看或修改。不同项目及同一项目不同工序允许并行。项目选择列表左侧突出主项目名称、右侧小字展示分期项目名称，选中结果仍只显示分期名称。工序按 `plannedStartTime` 默认最早一项，`processName` 按 `work_type` 字典回显并允许切换；计划周期和剩余工期均跟随当前工序，剩余天数按该工序 `plannedEndTime - 当天 + 1` 计算并包含当天。定位通过 `/project/location/list` 遍历全部实施地点，使用高德 `gcj02` 坐标按最近地点判断固定 200 米范围，未配置地点时禁止签到；位置正常时不提交打卡现场照片，位置异常时原因和现场照片同时必填。签到成功后在实施日志顶部直接显示接口返回的完整 `signInTime`。仅当前工序现场负责人加载并看到其他参与人员、计划外协和已出库物料，非现场负责人隐藏这三部分且不校验、不提交相应字段。实施用料以 `/project/materialAccount/page` 的 `plannedQty/outboundQty` 为数量来源，仅用 `/project/materialPlan/list` 按物料补齐草稿必传的 `materialPlanId`，不再拼装出库申请及明细。车辆手工填写；实施位置由操作人填写并统一提交 `implementLocationName`。参与人员 ID 以逗号拼接的 `internalParticipantIds` 提交；外协只校验和提交 `outsourceMemberId`、人数、工时，用料按 `materialPlanId` 提交，用料弹层支持对当前可选结果全选。现场照片和视频合并在同一“现场影像”区域，合计最多 5 项且视频单段不超过 60 秒；照片生成定位、经纬度和当前时间水印后，与视频一样在选择完成时立即调用 `/sys/common/upload`，`biz` 传“分期 ID/”，草稿只把返回路径统一写入现有 `photos` 字段，恢复时在同一列表按文件类型渲染。
- 领料申请：先选择 `usageType`。项目用料（`PROJECT`）进入页面即通过 `/project/member/participatedProjects` 加载当前用户已接受邀请的项目分期，并传 `periodStatus=IMPLEMENTING,DEBUGGING,DEBUG_COMPLETED,IMPLEMENT_COMPLETED,INTERNAL_ACCEPTING,ACCEPTING`，只保留计划审批完成后至验收完成、尚未进入质保的分期（`DEBUG_COMPLETED` 兼容历史数据）；项目筛选只匹配主项目名称或分期项目名称，选择列表左侧突出主项目名称、右侧小字展示分期项目名称，选中结果只展示分期名称，不展示项目单号或 ID。选定分期后不预加载物料，点击“添加可申请物料”时才按页读取该分期 `/project/materialAccount/page`，使用 `keyword` 搜索编码、名称、品牌或型号，滚动到底继续加载并支持跨页多选；只显示 `availableApplyQty > 0` 的物料，申请数量不能超过后端计算的当前可申请数量。候选项及领料明细将 `materialCode` 放在物料名称同行右侧，已选明细可直接删除。“全选/取消全选”仅作用于当前已加载且符合搜索条件的候选项。维修用料（`MAINTENANCE`）和劳保用品领取（`LABOR_PROTECTION`）不关联分期，读取 `/stock/material/list` 全部物料。三类均提交 `/stock/apply/add`，固定 `applyType=OUT`、`bizType=PICK` 并携带对应 `usageType`；项目用料额外传当前分期 `periodId`。申请头不传 `deptId/deptName/projectName/projectNo/applyUserName`，`itemList` 每项只传 `materialId/unitQty/unitName`，分期和物料详情仅用于页面展示。
- 还料、巡检、邀约和车辆新增记录：PC 端没有找到完整且一致的写入契约，暂保留 Mock/待接状态。

### 3.3 库管端 `src/pages/stock/`

- 首页出库执行待办按 `actionKey/todoType=STOCK_OUT_EXECUTE` 分流，使用 `actionParams.applyId` 跳转 `/pages/stock/materialDetail?id=...&from=stockOutTodo`，不使用 `bizId/bizSubId` 兜底。保留页面权限；详情按 `mtl:goods:io`、审批状态 `1` 和执行状态 `PENDING/PARTIAL_EXECUTED` 控制出库，提交前重查申请头。返回首页自动刷新待办列表及数量，页面仍由后端控制数据和操作权限。

- 列表按 `applyType=OUT/IN` 调用 `GET /stock/apply/list`。
- 详情并行调用 `GET /stock/apply/queryById` 和 `GET /stock/apply/items`。
- 待出库记录必须进入详情办理，不在列表直接执行整单。出库物料显示审批数量、实时库存、已出库数量、待出库数量；审批数量优先使用 `approvedQty`，历史空值回退申请数量，待出库数量为审批数量减 `executedQty`。
- 有待出库数量且 `currentUnitStockQty` 大于 0 的已审批明细默认全选；库管可多选批量出库，也可逐项填写不超过“待出库数量与实时库存较小值”的部分数量。一次提交使用 `itemIds + items[{ itemId, executeQty }]`，成功后刷新详情继续处理剩余量。
- 审批通过/驳回接口 PC 端已有 `/stock/apply/approve|reject`，但移动端当前页面定位为执行出入库，尚未增加逐项审批 UI。

## 5. 接口依据与验证规则

接口事实源为 Apifox 项目 `8679942`。2026-08-25 已通过其当前公开接口文档逐项复核，并与 SHKJ-OA 当前开发环境和 API 封装交叉检查；PC 代码只作为调用方式参考，路径或字段冲突时以当前 Apifox 为准。每次联调至少验证：请求 URL、query/body 位置、字段名、业务 code、分页结构、空数据、无权限和页面回显。

普通业务页使用 uni-app 原生导航并传 `PageLayout :navbarShow="false"`；`PageLayout` 内置的自定义 `wd-navbar` 仅供弹层和明确需要自定义返回/右侧操作的页面使用，不删除组件结构。

## 6. 后端环境

- SHKJ-OA 当前仓库的 development 配置指向 `http://10.10.10.12:16809/shouhuiApi`。移动端本机 development 配置当前为 `http://10.10.10.11:16809/shouhuiApi`，production 仍为 `http://192.168.18.2:16809/shouhuiApi`。三者存在环境差异，必须由实际部署地址确认后统一；本轮没有覆盖用户刚修改的移动端开发地址。
