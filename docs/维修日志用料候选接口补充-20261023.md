# 维修日志用料选择与后端待补字段

> 已被新版接口替代：以下为早期接法记录，不再作为当前实现依据。当前用料通过 `/repair/work/submit` 的 `materialItems` 随日志提交；候选直接读取维修详情返回的 `outboundQty/availableUseQty`。不再查询库存申请明细，不再调用独立 `/repair/material/use`。见《维修日志用料新版对接与时间轴-20261023.md》。

## 移动端本次调整

- 用料交互参考项目实施日志：选择物料（多选）→ 逐项填写本次用量 → 登记；自动关联当前维修日志，不再让用户手动勾选用料记录。
- 当前候选：`GET /repair/order/detail?id=工单ID` 的 `materialLinks`，筛选本人 `handlerUserId`、`linkType=PICK`；按 `stockApplyId` 查询 `GET /stock/apply/items?applyId=申请ID&pageNo=1&pageSize=20`，用 `stockApplyItemId` 匹配库存明细 ID，只保留 `executedQty > 0` 的实际出库明细。分页读取，不查全部物料库。
- 登记：`POST /repair/material/use`，传 `orderId/workRecordId/pickLinkId/quantity/description`。`pickLinkId` 是维修关联 ID，不是库存明细 ID。成功后刷新维修详情，将本次 `workRecordId` 下的有效用料 ID 自动放入日志 `materialUseIds`。
- 每项用量大于 0、最多 4 位小数；目前仅能本地校验不超过实际出库总量，实际剩余余额仍由登记接口校验。页面明确显示“可用量待接口返回”，没有伪造可用余额。
- 多笔逐项登记，不具备批量事务性。成功项从未登记列表移除；后续失败只保留未成功项，避免重试重复登记。网络结果不确定时停止登记，要求返回详情核对。

## 项目实施当前参考接口

`GET /project/materialAccount/page?periodId=分期ID&pageNo=1&pageSize=200`

项目实施日志使用 `outboundQty`（出库量）、`availableUseQty`（可用量）、`materialName/model/baseUnitName`（名称、型号、单位）。这是项目台账，不保证限定当前维修单和当前申请人，因此不能直接用于维修候选。

## 请后端补充（建议契约，尚未接入）

优先在现有 `GET /repair/order/detail` 的 `materialLinks` 每笔 PICK 明细增加：

| 字段 | 含义 |
| --- | --- |
| `outboundQty` | 本笔实际出库量，不是申请量或审批量 |
| `availableUseQty` | 本人此单此笔当前可登记的剩余量，包含退库、核销、已登记待确认等占用口径 |
| `materialName`、`brand`、`model`、`baseUnitName` | 选择物料需要的展示信息 |

保留 `id`、`stockApplyId`、`stockApplyItemId`、`handlerUserId`，避免同物料不同领料批次混用。可用量必须由后端权威计算，明确待确认使用是否已占用，不由前端用申请数量减算。

若领料明细较多，建议另提供分页“本人本单已出库可用物料”候选接口，参数为 `orderId/pageNo/pageSize/keyword`，用户身份取登录态；返回上述字段和 `total`。具体路径由后端确定，不视为现有接口。

后端补齐后：取消逐申请查询库存明细，直接按 `outboundQty > 0 && availableUseQty > 0` 筛选；页面展示真实可用量并校验数量上限，登记接口仍须并发校验。当前尚未完成真实余额显示、余额为零过滤与前端余额上限校验。
